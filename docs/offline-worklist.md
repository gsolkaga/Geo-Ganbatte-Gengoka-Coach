## 1. v1 の評価記録（最優先）

**アプリが `data/runs/*.json` に自動で保存する。手で形式を作る必要はない。**

`RunRecord` は以下を保持しており、**8/17 に v2 へ再投入できることを確認済み**である。

```
id  ts  variant  questionId
answer.slots      14 スロットの state / plain / terms  ← これがあるので再投入できる
answer.candidates 候補国と確信度
answer.decisiveSlot  answer.reasoning
result.models[]   モデルごとの status / feedback / rawContent / finishReason / 計測値
```

### 守ること

- **`variant: 'v1'` で取る。** v2 は 8/17 以降
- **4 モデルで採点する。** 1 モデルで済ませない
  - 1 モデルの当たり障りのない励ましより、**4 モデルが揃って中身のないことを言う**方が証拠として強い
  - 「モデルを替えれば解決する」という反論を先に潰せる
- **3 問以上。** 10 問あればよいが 3 問で記事は成立する
- **`data/runs/` を消さない。v1 の出力は再現できない**
- 打ち切り（`status: 'truncated'`）が出ても**それも記録である。** 消さない

### 消費

`3〜10 問 × 4 モデル = 12〜40 リクエスト`（v1 は正規化しないため 1 プレイ 1 モデル 1 回）

### 手順（B が実装済み。コードで完結する部分は全部できている）

```
Copy-Item .env.example .env      # 3 本の鍵を埋める
node tools/measure-concurrency.mjs   # 4 リクエスト。並列の可否を測る
npm run dev                          # 別ウィンドウで起動しておく
node tools/add-question.mjs --country JP --lat 35.123 --lng 139.456 --difficulty 1
```

**出題する 10 カ国は確定している。** `curriculum.md` の出題リスト。

```
JP  KR  TH  BR  AU  IS  BG  RU  KZ  KG
```

- `HTTP 422` は**仕様どおりの不採用**（著作権表記が Google 以外など）。別の座標で再試行する
- **メタデータ照会は無料でクォータも消費しない。** 何件試してもよい
- `measure-concurrency.mjs` が「直列に落とす」と出たら、**報告だけしてそのまま進める**
  （`grade.post.ts` の `Promise.all` を 1 箇所替えるだけなので 8/17 でよい）

プレイ時の注意。

- **分からないスロットは「未確認」のまま。「見えない」にしない**
  （`unknown` と `absent` の区別が本アプリの中心的な規約である）
- **「4 モデルで同時に採点する」にチェックを入れる**（既定はオフ。1 プレイ 4 リクエスト）
- `grading-prompt.md` の「記録すべき観測点」6 項目を見ながら記録する
  - **`summary` が当たり障りのない励ましになっているか**が章 6 の中核である

### 記録は push する

**`data/runs/` と `data/usage.jsonl` を commit して push する。**
これがないと 8/17 に Kiro が v2 との比較を組めない。

```
node scripts/check-secrets.mjs    # 公開前の点検。画像とキーの混入を検出する
git add data/ ; git commit -m "v1 の評価記録" ; git push
```

**スクリーンショットは push しない**（`.gitignore` が画像を全除外している）。ローカル保管。

## 2. スクリーンショット

**リポジトリに入れない。** `.gitignore` で画像拡張子を全除外している。

そして**アプリの画面を撮ると Street View の iframe が写る。**
規約でキャッシュ・再配布が禁止されているため、そもそも入れるべきではない。

### 撮り方

- **採点結果のパネルに限ってクロップする。Street View の映像を含めない**
- 記事で見せたいのは採点出力であって風景ではないので実害はない
- ローカルに保管し、**Qiita に直接添付する**（Qiita が画像をホストする）

### 撮っておきたいもの

- v1 の 4 モデル分の `feedback` が並んだ状態（**章 6 の中核**）
- `judgmentUnavailable` が表示されている箇所
- 打ち切りが起きたパネル（`content` 0 文字 / `reasoning` だけ伸びる様子）
- さくらのコントロールパネルの利用量（**作業前と作業後**。トークンが写らない範囲で）

### 持ち越した小さな課題：ペインの縦比

**些末だが忘れないように記録する。** 機能はしているので急がない。

採点後のペイン高さを `60dvh` にしたため、左列の縦比 `7fr:3fr` で回答欄が約 18dvh になり窮屈である。
回答を読み返しながら講評を見る場面で、回答欄がほぼ潰れる。

考えられる対処。

- 採点後だけ縦比を変える（`6fr:4fr` など）
- ビューワに最大高さを与え、余りを回答欄へ回す
- 入力中は 7:3、採点後は回答を読み返すので比率を入れ替える

**入力中の比率は現状で問題ない**（風景を大きく見たいので 7:3 が正しい）。
変えるのは採点後だけでよい。
