## 4. 「短く書け」と「必ず示せ」が競合したときに短い方を選ぶ

`gemma` の応答。

```

```

本文 358 字。**4 モデルで最短。**

プロンプトには両方書いてある。

- 「学習者を励ますだけの内容を書かない。**次に何を見るべきかを必ず具体的に示す**」

## 6. 一番重い問題：AI が正当な観察を「欄の間違い」として指導した

`Kimi` の `discoveries`。

> `bollard`（車道脇の短い杭・ポール）の欄に「ガードレールが黄色い」とあります。
> **ガードレールはボラードではないため、今後は欄の使い分けに注意してください。**
> ただし、色の観察自体はできており、見落としではありません。

**この指導は、この領域では誤りである。**

ガードレールとボラードは一体化することがある。学習者自身の口述から作った
`data/bollard-axes.json` に、その軸が入っている。

```json
{
  "id": "guardrail_relation",
  "label": "ガードレールとの関係",
  "values": ["standalone", "mounted_on_guardrail",
             "guardrail_post_serves_as_bollard", "mixed", "unknown"]
}
```

**`guardrail_post_serves_as_bollard`** ＝ ガードレールの支柱がボラードの役目を果たす。
実在する分類であり、`bollard` 欄に書くのは正当である。

### なぜこうなるか

**v1 は隣接スロットの情報を持っていない。**

コードは `filedElsewhere`（隣接スロットに記述がある）を計算できるが、
それには正解タグが必要である。v1 では `null`（判定不能）で渡している。

AI は自分の一般常識で「ガードレールとボラードは別物」と判断した。
**一般には正しい。この領域では正しくない。**

### 評価すべき点

`Kimi` は続けて「**ただし、色の観察自体はできており、見落としではありません**」と書いている。
**分類の指摘と観察の評価を分けている。** 4 モデルで唯一である。

そして同じ応答の中でこうも書いている。

> 今回これらが読めなかったのは地点の条件によるものであり、**あなたの見落としではありません。**

**指示していない配慮を自分で出している。** v2 で `blindSlots` として渡す内容と同じ向きである。

## 8. 辞書を渡していないのに一般論を断定した

`gpt-oss` の `vocabulary`。

| 項目 | 値 |
|---|---|
| `learnerWrote` | ガードレールが黄色い |
| `canonicalTerm` | **`bollard`** ← スロット ID。用語ではない |
| `note` | 日本では道路分離用のボラードは白や銀色が多く、黄色は工事区間や特定の地域で見られることがあります |

2 つ問題がある。

1. **`canonicalTerm` にスロット ID を入れている。** 用語辞書の用語名を期待していた欄である
2. **辞書を渡していないのに国別の傾向を述べている。**
   プロンプトは「正式な用語は用語辞書に載っているものだけを使う」と制約している。
   v1 では辞書が空なので、**本来この欄は空になるべきだった**

## 9. `discoveries` の誤用が 2 モデル

`discoveries` の定義は「`other` スロットの記述が正解タグの `other` と対応した場合、
**名前のない手がかりを自力で見つけたこと**を認める記述」である。

学習者の `other` は「見えない」であり、**該当する内容は無い。**

| モデル | `discoveries` の中身 | 件数 |
|---|---|---|
| `gpt-oss` | 正解の説明と助言 | 2 |
| `Kimi` | 助言・注意・励まし | **6** |
| `gemma` | （空） | 0 |
| `Qwen` | （空。打ち切り前に `[]` を出力） | 0 |

**埋める内容がない欄に、別の欄の内容を流し込んでいる。**

これは学習者のスロット記入と同じ現象である。`bollard` の欄に
ガードレールの記述が入るのと、構造として変わらない。

> **枠を与えれば埋めようとする。埋める材料が無ければ、近い材料を持ってくる。**
> 人間にも AI にも起きる。
