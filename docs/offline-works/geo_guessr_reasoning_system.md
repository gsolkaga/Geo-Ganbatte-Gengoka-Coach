# GeoGuessr 推論型学習アプリ：KIRO向け設計仕様

## 1. 目的

このプロジェクトは、GeoGuessrの国判定を「大量のメタを暗記するゲーム」ではなく、

**観察 → 地域候補生成 → 候補比較 → 情報による絞り込み →
否定要素による除外 → 国・地域決定 → 結果からフローチャート更新**

という推論プロセスとして学習できるアプリにする。

最重要方針は、**未知のメタに遭遇しても、既知の情報から合理的に候補を絞れる能力を育てること**。

## 2. ユーザーの認知・記憶特性

ユーザーは、孤立した事実の暗記よりも、因果関係・順序・条件分岐を伴う情報の記憶を得意とする。

GeoGuessrでも、

> A = B

という断片的説明より、

> Aを見た → B/Cが候補 → Dを見た → Bを除外 → Cが優勢

というフローチャート型の説明を理解しやすい。

したがって、教材は「メタ辞書」ではなく**推論グラフ**を中心にする。

## 3. 日本の電柱メタと世界の電柱メタ

日本の電柱については、電力会社を判別してリージョンゲスに使える。これは単純暗記ではなく、形状・配線・付属物などを条件分岐する複雑なフローチャートが形成されているためと考えられる。

世界の電柱では逆に、

-   強いメタ
-   特徴的な成功例
-   覚えている特殊形状

だけを断片的に記憶している。

現在比較的覚えている例は、ギリシャのハープ型電柱、八角形電柱、四角形電柱。ただし八角形／四角形は単独では不安で、複数本確認したい。

教材では「この電柱 =
この国」ではなく、**この電柱を見たら次に何を確認するか**まで説明する。

## 4. 基本観察フロー

1.  **大分類**\
    植生・路面状況などから、アジア／欧州／アフリカ／南米／北米／特殊地域などを大雑把に推定。

2.  **絞り込み要素の確認**\
    道路なら中央線・線の色／種類／本数・横断歩道・路肩。文字なら言語・文字体系・周辺地域。

3.  **地形・景観との整合性**\
    山、丘、平地、畑、田、森林、土の色、柵などから「この周辺ならこういう景色になる」という地理的整合性を見る。

4.  **特徴的メタを探す**\
    ボラード、標識、道路設備、電柱、ナンバープレート、信号、看板など。

5.  **組み合わせを探す**\
    弱いメタでも、複数が同じ国を指せば強い。

6.  **否定要素を見る**\
    その国にはほぼ存在しないものが出たら候補から外す。

7.  **過去の風景記憶と照合**\
    類似する近隣国・地域を思い出す。

8.  **決定**\
    強いメタ、複数の弱メタ、否定要素、景観整合性などを総合して判断。

## 5. 情報の3段階

### 候補生成

植生、気候、地形、土壌、建築、道路全体の雰囲気。

### 候補絞り込み

道路標示、標識、ナンバープレート、電柱、ボラード、信号、街路設備、言語。

### 確定・強化

国固有の看板、道路設備、ボラード、電柱、ナンバープレート、特定国でしか成立しにくい組み合わせ。

AIは「強メタ」という名前だけでなく、**何を否定し、何を候補として残すのか**を説明する。

## 6. メタの属性

``` yaml
meta:
  name: ""
  country: ""
  strength: weak | medium | strong
  role: candidate_generation | discriminator | confirmation
  visual_difficulty: easy | medium | hard
  standalone_reliability: low | medium | high
  combination_value: low | medium | high
  requires_context: true
  common_confusions: []
  next_checks: []
  explanation: ""
```

重要なのは、国特定能力と視覚認識可能性を分けること。

### カーメタの例

カタールのカーメタのアンテナは国特定には有用でも、ユーザーには細すぎて背景や縁石と同化し、認知しにくい。

したがって、

``` yaml
recognition:
  visible: false
  difficulty: extreme
  training_priority: low
```

のように、**知識として存在することと実戦の主要ルートにすることを分離**する。

## 7. グラデーション型の説明

ユーザーは「A=B」という断片より、地域差などの連続的変化を伴う説明を理解しやすい。

例：フィリピンのトゥクトゥク／トライシクルの屋根は北部から南部にかけて高さに差がある、というような説明。

教材では可能なら、

-   北→南
-   西→東
-   都市→地方
-   高地→低地
-   寒冷→温暖

などの連続変化として説明する。

## 8. よく観察する要素

### 道路

中央線、線の色・種類・本数、横断歩道、道路標示、路面の細かさ、アスファルトの粒、路肩、ガードレール、縁石。

### 街路

歩道、街路樹、露店、店舗、人出、ゴミ、店舗が歩道を塞ぐ程度、車両、街の豊かさの印象。

### 自然

植生、土の色、地形、丘、遠くの山、畑、田、柵、乾燥・湿潤、寒暖。

### 人工物

信号機、標識、路肩看板、ボラード、電柱、電気メーター、ナンバープレート、街灯、縁石、ガードレール。

### 言語・看板

言語、文字体系、ドメイン、電話番号、市外局番、通貨、特定企業・店舗・道路標識。

## 9. 既知の景観メタ

-   両側に低めの石垣があり、道が狭い田舎道 →
    イギリス／イングランドを想起。
-   ただの石垣 → ペルー／エクアドル候補。
-   大きい縁石などから欧州を想起することがある。ネパール／チベットなども候補になり得る。

これらは確定メタではなく、**候補生成情報**として扱う。

## 10. 既知の国・地域の混同

特に、

-   チェコ ↔ スロバキア
-   ノルウェー ↔ スウェーデン
-   ブルガリア ↔ ウクライナ
-   カナダ ↔ アメリカ
-   南米諸国間

を混同しやすい。

例：

### チェコ／スロバキア

ボラードが共通する場合があり、それ以上は勘になりやすい。

### ノルウェー／スウェーデン

植生・雰囲気中心。

### ブルガリア／ウクライナ

キリル文字までは分かるが、「ロシアではなさそう」以上の根拠が弱い。

### カナダ／アメリカ

現状はかなり難しく、「MAXIMUM」などを除くと強い根拠が少ない。

### 南米

全体的によく間違える。

これらは**confusion pair**として教材に登録する。

## 11. 国を確定する情報

特に価値が高いもの：

-   マレーシアの `AWAS`
-   インドネシアのタバコ広告 + `RP`
-   言語
-   ドメイン
-   電話番号
-   市外局番

ただし「看板を見たら国」とするだけでなく、候補集合のどこに効くかを説明する。

## 12. 重要な「知らない」の分類

### A. 本当に知識がない

例：ペルーの黄色＋黒のガードレール系メタ。

### B. 知識はあるが認知できない

例：カタールの極めて見つけにくいアンテナ。

### C. 既知の特徴が未知の特徴と混ざって認識できなかった

例：マレーシア電柱の既知の黒い四角プレート + 未知のテープ。

### D. メタは知っているが適用条件が分からない

例：八角形電柱だけでは国を決められない。

### E. メタは知っているが他国との差分を知らない

例：北欧の黄色い警告標識。

## 13. 実戦サンプル

### 13.1 カタール

ユーザーの推論：

``` text
砂漠
 ↓
中東
 ↓
アラビア語の標識
 ↓
イスラエル / オマーン / UAE 等
 ↓
ナンバープレート左側の帯らしきもの
 ↓
カタール
```

自信は約80%。正解。

解説ではカーメタのアンテナが決定打とされたが、ユーザーには視認困難。

**学習上の結論：**\
未知・低視認性メタを理由に、ユーザーの合理的な別ルートを否定しない。

### 13.2 マレーシア北部

推論：

``` text
熱帯植生 + 道路
 ↓
アジア
 ↓
インドネシアっぽい建築
 ↓
左側通行 + 黒っぽい横長プレート
 ↓
マレーシア / インドネシア
 ↓
JALAN
 ↓
インドネシアと判断
```

正解はマレーシア北部。

回答後、電柱の上部にある黒い四角プレートが既知のマレーシアメタだったことを確認。白なら別の島、本島なら黒という知識は持っていた。

しかし下部の2本のテープは未知だったため、画像を見た時点では既知メタとして認識しなかった。

**学習上の結論：**\
「電柱メタを知らない」のではなく、「既知メタが未知の付加要素と混ざったため認識ルートに入らなかった」。

### 13.3 ペルー

推論：

``` text
乾燥・砂漠
 ↓
コロンビア / エクアドル / ペルー
 ↓
ナンバープレートの色・サイズ
 ↓
建築
 ↓
ペルー
```

アルゼンチンやボリビアもあり得ると感じつつ正解。

解説ではガードレールの黄色＋黒の特徴がペルーメタとして紹介されたが、ユーザーは知らなかった。

**学習上の結論：**\
知らない強メタがあっても、景観・道路・建築・プレートなど別ルートで正解できる。

### 13.4 ブラジル

推論：

``` text
看板 + 店舗 + ナンバープレート
 ↓
ブラジル / アルゼンチン / パラグアイ
 ↓
標識裏が黒
 ↓
ブラジル候補上昇
 ↓
市外局番 51
 ↓
ブラジル南部
```

電柱はワッフル型と丸いコンクリート型が見えたが、ユーザー自身は決定材料として弱いと判断。

**学習上の結論：**\
複数の弱～中程度の情報を積み重ねて地域まで絞る推論の好例。

### 13.5 スウェーデン／デンマーク

推論：

``` text
北欧的な街並み
 ↓
レンガ建築 + 平坦
 ↓
デンマーク候補
 ↓
黄色い警告標識
 ↓
スウェーデン候補上昇
 ↓
スウェーデン南部 / デンマーク付近
 ↓
スウェーデン回答
```

正解はスウェーデン。ただしデンマークに置いた方がピン距離としては高得点だった。

**学習上の結論：**

-   「黄色い標識 = スウェーデン」と単純暗記しない。
-   景観メタと国を絞る標識メタが競合した例として扱う。
-   国判定とピン位置最適化を分離する。
-   今後は黄色標識 + 道路設備 + 建築 +
    他のスウェーデン要素という組み合わせで確認する。

## 14. 過去の誤認パターン

ユーザーが経験した代表例：

-   ペルー／ボリビアと思った → メキシコ
-   寒そうなチリと思った → カナダ
-   オーストラリアと思った → 南アフリカ共和国
-   イタリアと思った → アルバニア
-   バルト三国と思った → ドイツ

これは「失敗一覧」ではなく、**なぜその国に見えたかを記録するデータ**として扱う。

``` yaml
mistake:
  guessed: ""
  actual: ""
  reason:
    - landscape_similarity
    - architecture_similarity
    - vegetation_similarity
  lesson:
    - ""
```

## 15. 正解・不正解の評価

正解率と推論品質を分ける。

例えば、

``` yaml
answer:
  country: qatar
  confidence: 0.8
  reasoning_quality: high
```

のように、

-   回答
-   自信
-   推論品質
-   決定打
-   未知メタ
-   候補国
-   除外理由

を別々に保存する。

「正解したが説明できない」「不正解だったが候補まではかなり良かった」も重要な学習データ。

## 16. 教師データの構造

推奨する概念モデル：

``` yaml
round:
  observations: []
  initial_region: []
  candidates: []
  candidate_changes: []
  eliminations: []
  final_guess:
    country: ""
    region: ""
    confidence: 0.0
  actual:
    country: ""
    region: ""
  reasoning_quality: ""
  unknown_metas: []
  known_metas_not_used: []
  mistakes: []
  lessons: []
```

メタと推論ルールは別管理する。

``` yaml
knowledge:
  known_meta: []
  inference_rules: []
  confusion_pairs: []
  recognition_difficulty: []
```

## 17. AIによる教師データ補完

ユーザーが言及していない初級者向け情報はAIが補完してよい。

ただし、以下を明確に区別する。

-   **USER_DERIVED**：ユーザー自身の実況・経験・既知知識
-   **AI_SUPPLEMENT**：一般的な初心者向け補足
-   **UNVERIFIED**：AIの推測や要検証情報

ユーザー独自の推論方法を一般論に書き換えない。

``` text
問題
 ↓
ユーザー実況
 ↓
AIが観察を構造化
 ↓
候補国・地域を記録
 ↓
ユーザー回答
 ↓
実際の正解
 ↓
何が当たっていたか分析
 ↓
未知メタを分類
 ↓
既存フローチャートとの差分を抽出
 ↓

 ↓
教師データ更新
 ↓

```

GeoGuessr Daily
は単なる問題集ではなく、**ユーザー専用の推論モデルを継続的に更新するための実戦データソース**として扱う。

## 19. フローチャート／推論グラフ

最初から国別の巨大な決定木を作らない。

基本構造：

``` text
地域候補生成
 ↓
候補集合
 ↓
discriminator
 ↓
候補更新
 ↓
confirmation
 ↓
国決定
 ↓
地域・ピン最適化
```

例：

``` text
乾燥 + 高地
 ↓
アンデス候補
 ├─ ペルー
 ├─ ボリビア
 ├─ チリ
 └─ アルゼンチン
      ↓
道路設備
      ↓
プレート
      ↓
建築
      ↓
地形
      ↓
候補削除
```

メタはノード、観察結果は条件、候補の上げ下げはエッジとして扱える。

## 20. 今後のインタビュー

実戦画像を使い、以下を質問する。

1.  最初に何が目に入ったか
2.  最初にどの地域を想定したか
3.  何カ国を候補にしたか
4.  次に何を確認したか
5.  その情報で候補がどう変化したか
6.  何を理由に候補を捨てたか
7.  最終的な決定打は何だったか
8.  正解後に知らなかったメタは何だったか
9.  そのメタは視認できそうか
10. 単独メタか組み合わせメタか
11. 類似国が出た場合に何を追加確認するか
12. 新しい知識をフローチャートのどこに入れるか

「このメタを知っていますか？」だけではなく、**「この情報を見たことで候補がどう変化しましたか？」**を重視する。

## 21. KIRO実装時の優先順位

1.  ユーザーの実際の実況
2.  ユーザーが既に持っている知識
3.  ユーザーが認知できる視覚特徴
4.  ユーザーの混同パターン
5.  ユーザーが理解しやすい条件分岐
6.  AIが補完した一般的初心者知識
7.  極端に視認性の低いマニアックメタ

特に7は、知識として保持しても通常の学習ルートには優先的に入れない。

## 22. 最終設計思想

このアプリのコアは **Meta Database** ではなく **GeoGuessr Reasoning
Graph**。

目標は「全メタ暗記」ではなく、

-   初見から大地域を推定
-   観察すべき要素を選択
-   複数候補を作成
-   新情報で候補を更新
-   否定要素で候補を削除
-   強メタを発見したら利用
-   強メタを知らなくても別ルートで推論
-   類似国との違いを意識
-   国判定とピン位置を分離
-   結果から自分のフローチャートを更新

できるプレイヤーを育てること。

### 最重要原則

> **「国ごとのメタ一覧」ではなく、「候補がどう変化するか」を教える。**

そして、

> **「知らないメタがある状態でも正解できた経験」を積極的に教材化する。**

これをプロダクト全体の学習設計の中心に置く。
