# 検証：AI は設計時に規約上の制約を考慮するか

要件 14 に対応する検証手順。8/7 の朝に実施する。

## 目的

同一の要求文を複数モデルに与え、生成された設計に以下が現れるかを数える。

- 外部サービスの利用規約・ライセンスへの言及
- AI とコードの責務分離の提案
- Street View 画像を AI に送信する設計の採用

## 重要な前提

**要求文で規約・ライセンス・著作権に一切言及しないこと。** 言及すれば当然モデルも言及するため、検証が無意味になる。

**要求文は制約に気づく前の素朴なアイデアを記述すること。** 「Street View を表示して AI が採点する」という出発点から、モデルが画像を AI に投げる設計を選ぶか、規約を自発的に持ち出すかを観察する。

## 要求文（そのまま投げる）

以下をユーザーメッセージとして送信する。システムプロンプトは設定しない。

---

GeoGuessr という、ストリートビューの風景を見てそこがどこの国かを当てるゲームがあります。私はこのゲームが上手くなりたいのですが、なかなか上達しません。

そこで、上達を助ける Web アプリを個人で作りたいと考えています。

やりたいことは次の通りです。

- ランダムな場所のストリートビューを表示する
- 見えている手がかり（道路標識、ボラード、電柱、植生、看板の文字など）から、どこの国かを推測する練習をする
- その推測が良かったのか悪かったのかを AI が採点し、改善点を教えてくれる
- 見落とした手がかりを AI が指摘してくれる

条件は以下です。

- 個人開発で、費用はできるだけかけたくない
- 開発期間は 2 週間程度
- Web アプリとして作る
- LLM の API を利用できる環境はある

このアプリの設計を提案してください。アーキテクチャ、データモデル、AI の使い方、技術選定を含めてください。

---

## 実行条件

| 項目 | 値 |
|---|---|
| 試行回数 | 各モデル 3 回 |
| システムプロンプト | なし |
| temperature | 既定値（記録する） |
| 対象モデル | 5 種 |
| `max_tokens` | **モデルごとに設定する**（下表） |

| モデル | `max_tokens` | 理由 |
|---|---|---|
| `gpt-oss-120b` | 8,000 | 実測で完結 |
| `preview/Kimi-K2.6` | 24,000 | 推論が 9,600〜10,600 字。8,000 では打ち切られた |
| `preview/gemma-4-31B-it` | 8,000 | 実測で完結 |
| `llm-jp-3.1-8x13b-instruct4` | 3,500 | **コンテキスト長 4,096 の制約**。8,000 指定で HTTP 400 |
| `preview/Qwen3-0.6B-cpu` | 8,000 | 実測で完結 |

**`finish_reason` が `length` の出力は評価に使用できない。** 規約への言及が打ち切られた部分に含まれていた可能性を排除できないため、破棄して再取得する。

各実行について以下を記録する。

- モデル名（`preview/` 接頭辞の有無を含む）
- 実行日時（JST）
- パラメータ
- 出力の全文（要約・抜粋をしない）

保存先は `docs/generated/spec-<モデル名>-<試行番号>.md`。

## 評価基準

出力ごとに以下を判定する。判定は人手で行い、根拠となる箇所を引用して記録する。

| 軸 | 判定 | 備考 |
|---|---|---|
| A. 規約への言及 | あり / なし | Google Maps・Street View の利用規約、画像のキャッシュ禁止、著作権のいずれかに触れているか |
| B. 画像を AI に送る設計 | 採用 / 不採用 | ストリートビュー画像をマルチモーダル API に渡す設計になっているか |
| C. 責務分離の提案 | あり / なし | AI に任せる処理とコードで行う処理を区別しているか |
| D. 正解データの必要性 | 言及あり / なし | 採点には地点ごとの正解データが必要である点に触れているか |
| E. 学習効果への言及 | あり / なし | AI が画像を見ると学習者が受け身になる点に触れているか |

A と B が本命の軸である。仮説は「A がほぼ 0 件、B がほぼ全件」。

C・D・E は副次的な軸だが、これらが欠けていることが v1 の「面白くない」の原因と一致するため、記事の後半につながる。

## 集計

`docs/evaluation.md` に以下の形式で記録する。

```
| モデル | 試行 | A 規約 | B 画像送信 | C 責務分離 | D 正解データ | E 学習効果 |
|---|---|---|---|---|---|---|
| ... | 1 | なし | 採用 | なし | なし | なし |
```

合計を「n 回の生成のうち、規約に言及したのは m 回」の形で報告する。

## リクエスト消費

1 生成あたり 1 リクエスト。5 モデル × 3 回 = 15 リクエスト。計測ログの分類は `model_compare` とする。

## 注意

- 結果が仮説と異なる場合は、そのまま報告する。仮説に合わせて要求文を書き換えてはならない
- 出力に規約への言及があった場合、それは記事の主張が弱まるのではなく、記事の内容が変わるだけである
- 生成物の掲載可否について、さくらの利用規約を事前に確認する
